# AWS学習記録

## 1. 基本情報
- 学習日：2026-11-01
- 学習時間：30m
- 学習テーマ：nginxのログの確認

## 2. 学習目的
Linuxでnginxのログを確認し、webサーバーが突然動かなくなった際のログ解析などの復旧作業をトレーニングする。

## 3. 実施内容
- 1.nginxのファイルを確認する。
- 「sudo cat /etc/nginx/nginx.conf」

- 2.ディレクトリ内のフォルダを確認
- 「sudo ls -l /var/log/nginx/」

- 3.アクセスログの確認
- 「sudo tail -n 20 /var/log/nginx/access.log」
- ※次回に延期

## 4. 技術的な理解
【今回使用したコマンド一覧】
- sudo：管理者権限で実行
- cat：ファイルの中身を確認
- **ls**：ファイルやディレクトリの一覧を表示するコマンド
- **-l**：ファイルの権限や所有者、サイズ、更新日を確認可能
- tail：ファイルの末尾を表示
- -n 20：最後の20行を表示する
- 200：正常にリクエストが処理されたことを示すステータスコード
- 404：要求されたファイルが存在しないステータスコード
- 405：要求された通信方法が許可されていないステータスコード

【nginxに存在するログファイル】
- access.log：どのようなアクセスがあったか
- error.log：エラーや問題があった時の記録
- ※Amazon Linux 2023では通常ここに保存：/var/log/nginx/

【nginx.confの重要な部分 ※1.の実行結果による】
- server：webサイトの設定ブロック
- listen 80：IPv４で80番ポートを待ち受ける
- listen [::]:80：IPv6で80番ポートを待ち受ける
- server_name _：特定のドメイン名を設定しないデフォルトのサーバー設定
- root：webページのファイルを配置するディレクトリ

- access_log：アクセスログの設定
- /以下：アクセスログの保存先
- main：ログの書式

- send file on：ファイル送信を効率化する
- tcp_nopush_on：TCP通信でデータをまとめて送信するための最適化
- keepalive_timeout 65：HTTP接続を維持する時間の設定（秒）

## 5. 設計理由
- AWSのSGで80番ポートを許可する & nginxが80番ポートを待ち受ける、という両方の設定があって初めて通信が成立するため

## 6. 発生した問題と解決方法
- 発生した問題：外部からの不審なアクセスを確認した。
- 原因：インスタンスのSGのインバウンドルールを0.0.0.0/0に設定したまま数時間放置したため。
- 対応：SGのインバウンド設定を閉じた。
- 解決結果：以後の不審なアクセスは無くなった。

## 7. 学習成果・確認結果
HTTP通信（80番ポート）はインターネット上から簡単にアクセスすることができるため、不正アクセスの可能性があり、
公開範囲を詳細に狭めることが大切であると学んだ。
一方で、インバウンドルールは初めからすべてのアクセスを許可していないため、設定に多大な時間がかかる可能性がある。
今回は0.0.0.0/0のみの設定のため大丈夫であったが、特定のアクセスを規制するためにネットワークACLなどのサービスについても実機演習を行ってみたいと感じた。

## 8. 今後の課題
アクセスログとエラーログの監視をすることで、実際の不正アクセスの可能性について知る。
