## 2. 学習目的
AWSで実際にインスタンスを起動し、nginxのアクセスログとエラーログを参照する。

## 3. 実施内容
- sudo tail -n 5 ~/access.logの実行
- sudo tail -n 5 ~/error.logの実行

## 4. 技術的な理解
- GET /~：~以降についての探索
- POST /~：~以降でリクエストやアクセスを表す際の言葉
- CONNECT ~：CONNECTメソッドによる通信要求

- notice：通知レベルのログ
- SIGCHLD：子プロセスが終了したことを親プロセスに知らせるシグナル
- exited with code 0：プロセスが正常終了したことを示す終了コード
- →このコードが残っていると言うことは、nginxのサーバープロセスが正常に終了したと言う意味

- 「sudo systemctl status nginx」
- →active (running)：現在Nginxが起動している
- →inactive (dead)：現在Nginxが停止している
- →failed：Nginxが起動に失敗している

- 「sudo grep -Ei '\[(emerg|alert|crit|error|warn)\]' /var/log/nginx/error.log-20261102 | tail -n 10」
- 重大なエラーが出ていないかを確認するコマンド

## 5. 設計理由
- 生成AIの助言通りにコマンドを入力した。
- nginxの起動/終了のログの確認、及び外部からのアクセスの記録を確認するためのコマンドを使った。

## 6. 発生した問題と解決方法
- 発生した問題：[error] open() /~というエラーが発生していた。
- 原因：EC2にファイルが存在しないことが原因。
- 対応：特になし
- 解決結果：今回は0.0.0.0/0のアクセスを許可していたため、ファイルは空の状態にしていたので、正常な反応だとした。

## 7. 学習成果・確認結果
- 実際にアクセスログおよびエラーログを確認し、どのようなアクセス/エラーがあったか確認できた。
- 0.0.0.0/0のインバウンド通信を許可していないのに、アクセスログとエラーログが残っていた。
- →「sudo -ls -l --full-time /~」で確認したところ、インバウンド通信を試しに許可していた頃のログが残って表示されていたことが判明した。
- 「sudo systemctl status nginx」でnginxの稼働状況を確認することができた。
