## 2. 学習目的

## 3. 実施内容
- 「df -h」：ディスクの容量を確認する。
- →ディレクトリの空き容量を確認し、不要なログやファイルで圧迫されていないかを確認する。

- 「free -h」：メモリの全体容量、使用量、空き容量を確認する。
- →メモリの空き容量および、可用容量を確認できる。
- →サーバーやwebアプリケーションの動作が遅くなった際の初期調査として利用できる。

- 「ps aux」：現在動作しているプロセスの一覧を確認する。
- →「systemctl status」：現在のサービスの状態
- →「journalctl」：サービスの起動/停止のなどの履歴の確認
- ※これらを組み合わせることで、サーバーやwebサイトの障害調査に役立つ。

## 4. 技術的な理解
【コマンド詳細】
- df：ディスクの空き容量を確認するコマンド
- -h：容量を読みやすい単位(MG/GB)で表示するオプション

【ディレクトリ詳細】
- /：Linux全体の基本となるディレクトリ
- /boot/efi：OS起動に必要な情報を保存する領域
- /tmp：一時ファイルを保存する領域

【メモリ詳細】
- ※total, used, shared, buff/cacheの説明は省略
- free：現在全く使用されていないメモリ
- available：新しい処理に利用できると見込まれるメモリ
- Swap：物理メモリが不足した際に、ストレージの一部をメモリの代わりに利用する仕組み。

【プロセス詳細】
※一部説明省略
- PID：プロセスを識別するための番号
- ％CPU：CPUをどれくらい使用しているか
- ％MEM：メモリをどれくらい使用しているか

## 6. 発生した問題と解決方法
- 発生した問題：以前EC2の起動とともに自動起動設定したnginxが起動しなかった。
- 原因：EC2の停止時に同時に停止したままの状態になってしまったと考えられる。
- 対応：「systemctl is-enabled nginx」で自動起動設定を確認し、「sudo systemctl start nginx」でnginxを起動、「sudo systemctl enable nginx」で自動起動設定を行った。
- 解決結果：自動起動設定をすることができた。

EC2の起動/停止は重要なタスクであると思うが、今回のような不具合が現れることも意識しておかなければいけないと感じた。
